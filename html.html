Start Class

Today we begin with the basics of making text look good on web pages. Think of HTML text tags like the tools in a word processor — bold, italic, underline, highlight. But unlike a word processor, HTML also has semantic tags that tell the browser what the text means, not just how it looks. This matters for screen readers and Google.

This is where you go from "someone who writes HTML" to "someone who writes good HTML." For years, developers used <div> for everything — headers, navs, footers, articles. It was a mess. HTML5 gave us semantic elements that tell the browser what each section IS. This helps screen readers navigate, helps Google understand your page, and makes your code readable. If you remember nothing else from today: stop using divs for everything.

Complete Semantic Element Reference
ElementWhat It RepresentsKey Rules

<nav>Major navigationOnly for major nav, not every link group
<main>Primary contentOnly ONE per page
<section>Thematic groupingMust have a heading
<article>Self-contained contentCould be independently shared
<aside>Tangentially relatedSidebars, pull quotes, ads
<footer>Footer for ancestorMultiple allowed
<figure>Media with captionWraps img, video, code
<details>Expandable contentContains <summary> as first child

<time>Machine-readable datedatetime attribute for machines
